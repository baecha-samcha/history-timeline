# 가독성 개선 검증 (2026-10-21)

표현 계층만 변경했다. 데이터 모델, 저장 API, 인증, 동기화 코드는 수정하지 않았다.

## 변경

- 텍스트 실측으로 레인을 배정하고 분류별 띠 안에서 기간/사건을 배치한다. 현재 데이터에서는 축소 줌도 110개 제목을 모두 표시한다. 밀도가 높으면 세로 스크롤이 길어진다.
- SVG 순서는 눈금/분류 → 흐름 → 기간 → 사건이다. 제목에 테마 배경색 헤일로를 적용했다.
- 사건 14px/500, 기간 13px/700, 연도 16px/700, 흐름 12px/500, 월 11px. 1년 단위의 연도 숫자를 수용하도록 열 간격을 넓혔다.
- 짧은 바는 외부 레이블, 조망 줌은 제목만, 중간 줌은 월까지, 상세 줌은 전체 날짜를 표시한다.
- 제목은 테마 텍스트 색을 사용하고, 바 내부만 배경 대비가 높은 흰색/검정 계열을 선택한다. 태그 텍스트 색은 일반/호버 배경 대비를 계산한다.
- 사이드바 제목/태그 검색, 제목 툴팁, 날짜 줄바꿈 방지, 항목 구분선을 추가했다.
- 흐름 제목은 별도 하단 행에서 확인하며, 제목 또는 곡선을 호버하면 해당 곡선을 강조한다.
- 모바일은 헤더 1행과 가로 스크롤 컨트롤 1행, 기본 닫힌 목록 오버레이, 44px 컨트롤, 현재 연도 표시를 사용한다.
- 모달 배경은 blur(2px), 검정 40% 딤. 상세 본문과 제목의 타이포는 유지했다.
- 로그인 부제의 고정 연도를 제거하고 favicon.ico/robots.txt를 추가했다.

## 검증 환경과 결과

시스템 Chromium + Playwright를 사용했다. 원본 코드를 브라우저 응답으로 제공해 computed style을 확인했다. 변경 전 사건 13px/400, 기간 11px/600, 흐름 11px/600, 연도 12px/600, 월 10px였다.

DB는 SELECT만 사용해 실제 기간 15개/사건 95개/흐름 13개를 읽었다. 로그인 자격 증명이 없으므로 운영 계정 로그인은 수행하지 않았다. 브라우저 테스트는 별도 컨텍스트에서 인증/데이터 응답을 가로채 제공했으며, 저장 API를 호출하지 않았다.

- 실제 110개 항목 × 8개 줌 × 두 테마: 사건/기간 제목의 getBBox 교차 0건, SVG 폭 경계 잘림 0건.
- 일반 제목 대비: 라이트 약 20:1, 다크 약 16.5:1. 캔버스 포함 보조 토큰 최소 대비는 라이트 약 5.4:1, 다크 약 8.3:1. 태그 텍스트도 4.5:1 이상.
- 1933년대 라이트/다크 화면을 캡처하고, 검정 태그 제목과 레이블 헤일로를 확인했다.
- 390×844: 문서 폭 390px, 헤더 약 111px, 목록 기본 닫힘 및 열기/닫기 확인.
- 검색, 모달 배경, PNG 다운로드 확인. 브라우저 JavaScript 오류 0건.
- `npm run build`, 합성 밀집 데이터 브라우저 회귀 테스트 통과.
- 공개 사이트 app.js와 작업 파일의 SHA-256 일치, favicon.ico/robots.txt HTTP 200 확인. 정적 파일을 직접 제공하므로 서비스 재시작은 수행하지 않았다.

기존 DB 통합 테스트는 공유 DB에 계정/사건을 쓰므로 이번 UI 검증에서는 실행하지 않았다. 모바일 검증은 Chromium 에뮬레이션이며 실제 기기 검증은 포함하지 않는다.

## 재실행

```bash
npm ci
# Chromium이 없다면 별도 설치 후 실행 파일 경로를 지정한다.
CHROMIUM_PATH=/usr/bin/chromium npm run test:readability
```

기본값은 메모리에 생성한 기간 15개, 사건 95개, 흐름 13개다. 테스트는 임시 포트의 정적 서버를 사용하며 데이터베이스에 접속하지 않는다. `READABILITY_DATA=/path/to/data.json`으로 같은 데이터 구조의 읽기 전용 스냅샷을 선택할 수 있다. 실제 데이터나 자격 증명은 저장소에 넣지 않는다. `READABILITY_OUTPUT`으로 스크린샷/JSON/PNG 저장 폴더를 지정할 수 있다 (기본 `/tmp/history-readability-test`).
